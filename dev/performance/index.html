    Tack Performance Results¶

    These numbers predate current behavior (note added 2026-10-05)

    The measurements below were taken before several changes that affect them:

    1. Safe floating-point math on CUDA and Metal (2026-10-03). Kernels are no longer compiled with fast math. CUDA compiles with --ftz=false --prec-div=true --prec-sqrt=true, and Metal with fast math disabled. CUDA transcendentals call the precise device math functions (sinf, expf, and so on) instead of the hardware special-function-unit approximations. The note below that explains the sin/exp speedups with SFUs no longer applies, and those rows can be expected to change. See Numerical Semantics.
    2. CPU threading policy repairs (2026-10-02 to 2026-10-04). The decision between a serial run and a thread fan-out was revised. See CPU Threading Policy.
    3. CPU disjoint-array specialization (2026-10-03). The CPU backend now compiles a separate noalias variant for calls whose written arrays don't overlap other arrays. See Memory and Aliasing.
    4. Queued GPU launches (Metal 2026-10-09; CUDA, HIP and Level Zero 2026-10-14). A kernel call on a GPU backend returns once the launch is queued, and the host waits only when it reads an array or calls tack.sync(). The two reproduce scripts below time a call without tack.sync(), so their GPU columns would now time the launch rather than the kernel.
    5. The CPU thread pool (2026-10-14). CPU fan-outs go through a thread pool JIT-compiled from LLVM IR: 3–5 µs per hot fan-out on a 2 GHz Xeon, where the executor cost about 60 µs per worker. A new tack.Array is no longer filled. See CPU Threading Policy.

    Re-measurement is planned. Until then, read the tables below as a historical record. They have not been edited.

    64 MB of f32 data (16,777,216 elements), median of 30 trials after warmup.

    Reproduce: uv run python benchmarks/bench_64mb.py

    Notes¶

    • Metal GPU vs CUDA GPU are in the same ballpark (~19-29 G elem/s) despite very different architectures. Both are memory-bandwidth limited for simple kernels, compute-limited for transcendentals.

    • CPU/NumPy gap between Mac and Linux is mostly memory bandwidth: Apple Silicon unified memory delivers ~100-200 GB/s vs ~4 GB/s effective on this DDR3 Xeon box. The CPU itself (Sandy Bridge 2012 @ 2.0 GHz, AVX1 only) also contributes to the gap.

    • FILL hits 62 G elem/s on CUDA (write-only, no reads) — close to the 4060 Ti's theoretical 288 GB/s (62G × 4 bytes = 248 GB/s).

    • sin/exp show the largest CUDA-vs-CPU speedup (34-45x) because CUDA's Special Function Units (SFUs) compute transcendentals in hardware.

    • reduce favors Metal (39G vs 26G) — likely benefiting from unified memory avoiding a writeback path for partial sums.
