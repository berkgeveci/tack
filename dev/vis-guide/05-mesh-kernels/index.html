    Write mesh algorithms¶

    Use td.for_each when an operation is naturally expressed per cell, face or edge. Tack supplies a view of the mesh and compatible views of its fields; Views explains what they are and where they come from. Your kernel can use geometry and interpolation without manually switching on cell type or maintaining a connectivity parser for every representation.

    An operation on each value of a field alone, such as scaling it, needs no mesh: pass field.values to an ordinary kernel and loop over range(len(values)). That is also how to loop over points.

    Read Device Functions and Templates when the kernel syntax is new. The built-in filters use the same dataset API as the examples here.

    Separate an algorithm from storage layout¶

    This kernel computes each cell's mean corner temperature:

    @tack.kernel
def corner_mean(cells, temperature, out):
    for c in cells:
        total = 0.0
        for j in range(cells.NUM_POINTS):
            total += temperature.corner_value(c, j)
        out[cells.entity_id(c)] = total / cells.NUM_POINTS

    cells is a domain view. temperature is a field view, so temperature.corner_value(c, j) resolves through that field's space and storage. It can read a stored value or evaluate an implicit array.

    The dispatcher launches once per compatible group: usually each cell shape, with further grouping for varying space order or size buckets. NUM_POINTS is consequently a constant for this kernel specialization. It is eight for a hex and five for a pyramid; the source stays the same.

    This corner mean is a teaching algorithm. It is not a general quadrature rule for integrating a field over an arbitrary cell.

    Use global ids for global output¶

    The loop variable c belongs to its view. On structured cells it can represent several indices rather than an ordinary integer. Pass it to view methods; use cells.entity_id(c) when indexing output storage allocated for the entire mesh. A group-local index is not an output cell id on a mixed mesh.

    td.for_each(kernel, data, "cells", *args) supplies the domain view as the first argument. Each td.Field in the remaining arguments becomes a matching field view. A raw Tack array stays a raw buffer; the kernel is responsible for indexing it correctly.

    Run over a selection and initialize unwritten output¶

    On the two-cell mesh, select just the right cell:

        data.sets["right"] = td.Set(data, "cells", [1])
    means = tack.zeros((data.num_cells,))
    td.for_each(corner_mean, data, "right", data.fields["temperature"], means)
    # Only cell 1 is written. Cell 0 retains its initialized zero.

    The output has room for all cells because the kernel writes global ids. tack.zeros initializes the cell that this selected launch will not visit. The result is [0, 3.25]. Uninitialized allocation would be appropriate when every element is written before anything reads it.

    A cell or face set's name is a domain. For a point set, iterate its ids in an ordinary kernel; point sets do not currently supply a dataset domain view. Sets belong to their topology, so a set from an earlier filter input cannot be substituted for a set on its renumbered output.

    Visit a space's nodes¶

    td.for_each(kernel, data, space, *arrays) runs a kernel over a space's nodes, each once, where td.interpolate evaluates its function: an order-2 H1 space's points, edge middles, quad face centers and cell interiors, an L2 space's corners per cell. Each node has nodes.node_dof(i, j), where its value goes in the space's array, and nodes.node_position(i, j):

    @tack.kernel
def sample(nodes, values):
    for i in nodes:
        for j in range(nodes.node_count(i)):
            x = nodes.node_position(i, j)
            values[nodes.node_dof(i, j)] = x[0] * x[1]

    Work at a field's nodes¶

    A field view numbers its own cell's nodes, whatever its space, order or shape: NODES of them (a constant, so a loop over them unrolls), node k at parametric coordinates node_parametric(k), its value dof(c, k), stored at dof_index(c, k) in the field's array. That is enough to compute a field of one space from fields of others without projecting first. To add an order-1 field p to an order-2 field q into a new order-2 field, read p through its own basis at each of q's nodes:

    @tack.kernel
def add_at_nodes(cells, p, q, out):
    for c in cells:
        for k in range(q.NODES):
            out[q.dof_index(c, k)] = p.value(c, q.node_parametric(k)) + q.dof(c, k)


p, q = data.fields["p"], data.fields["q"]      # H1 of order 1 and of order 2
space = q.space
out = tack.empty((space.size,), tack.f32)
for group in data.launch_groups("cells", [p, q]):
    add_at_nodes(data.domain_view("cells", group), p.view(group), q.view(group), out)
s = td.Field(space, out)

    The same kernel runs on every shape and every space: a hexahedron's 27 quadratic nodes, a segment's 3, an order-3 tetrahedron's 20, an L2 cell's own, a Constant cell's one at its centre. Cells that share a node write the same value to the same place, so the result does not depend on which one writes last. Here it equals td.project(data, p, space) plus q, since p lies in the order-2 space.

    NODES is the field's, not the shape's. The shape's NUM_QUADRATIC and quadratic_node(k), which a view also has, are the quadratic element's nodes whatever the field: an order-1 field has fewer, an order-3 field more, and a segment none, so a loop over them writes nothing. A serendipity field's NODES are the corners and edges it stores, which come first; it computes the rest. In a Bernstein basis (basis="bernstein"), dof(c, k) is a coefficient, not the field's value at node_parametric(k) (the Greville point), so a kernel that writes values there writes a Lagrange interpolant's values into a Bernstein field: right only where they agree, as they do for multilinear fields.

    for_each over a space (above) visits each stored value once; a loop over a field view's nodes visits a shared node once per cell holding it, but has the cell's other fields at hand.

    Parametric and world coordinates have different meanings¶

    cells.parametric_center() returns a location in the cell's reference element. temperature.value(c, pc) evaluates the field there, and cells.position(c, pc) maps it into physical space. A parametric coordinate is not a world-space [x, y, z] query point.

    Likewise, temperature.parametric_gradient(c, pc) differentiates with respect to the reference coordinates. A physical gradient also needs the geometry's Jacobian mapping. Use td.gradients for the built-in physical calculation; use probing when query positions are given in world coordinates.

    Compute one oriented flux per face¶

    A face has side 0 and possibly side 1. Its normal points out of side 0; faces.num_sides(f) == 1 identifies a boundary face. Reading a neighbouring cell must be guarded when that side is absent.

    For the vector field v(x,y,z) = (x,y,z), the following kernel computes its integrated normal flux, dot(v, normal) * area, at each face's center:

    @tack.kernel
def integrated_flux(faces, centers, normals, areas, out):
    for f in faces:
        e = faces.entity_id(f)
        velocity = centers[e]                   # v(x,y,z) = (x,y,z)
        out[e] = velocity.dot(normals[e]) * areas[e]

    Geometry, centers and output values are raw device fields here, indexed by the face's global id. Each iteration owns one output, so it needs no atomic. The normal and center fields use the same topology's face numbering.

        faces = data.topology.faces()               # derive incidence once
    geometry = td.face_geometry(data)
    centers = td.face_centers(data)
    flux_values = tack.empty((faces.num_faces,))
    td.for_each(integrated_flux, data, "faces", centers.values,
                geometry.normal.values, geometry.area.values, flux_values)
    flux = td.Field(td.Values(data, "faces", oriented=True), flux_values)
    net_outflow = td.net_flux(data, flux)       # integrated flux, per cell
    divergence = td.divergence(data, flux)    # net_outflow / volume: 3 for v = (x,y,z)

    td.net_flux is an outward sum of the supplied face values: a face adds to its side-0 cell and subtracts from its side-1 cell. It does not divide by cell volume. With integrated face flux as input, its result is integrated net outflow. td.divergence divides it by each cell's volume, the finite-volume divergence.

    Each example cell has volume 0.5, net outflow 1.5, and therefore average divergence 3. The sum of both cells' outflows is the boundary outflow 3; the internal face cancels. This independent balance catches orientation and association errors that a plausible image might hide.

    For a scalar transported by a constant velocity, td.upwind_flux provides the face calculation and returns an oriented field. Its boundary convention uses the one existing cell's value; a solver needing prescribed inflow must supply its own boundary treatment.

    Share face-based code with polyhedra¶

    Shape-based cells have compile-time corner counts. Polyhedra instead expose runtime num_points(c) and num_faces(c) counts. The following surface-area kernel walks each cell's outward faces and works on both paths:

        @tack.kernel
    def surface_areas(cells, out):
        # Every face of every cell, walked outward from the cell: the same code
        # for a hexahedron, a pyramid or a polyhedron.
        for c in cells:
            total = 0.0
            for k in range(cells.num_faces(c)):
                a = cells.side_position(c, k, 0)
                n = a - a
                for j in range(1, cells.side_num_points(c, k) - 1):
                    n += (cells.side_position(c, k, j) - a).cross(
                        cells.side_position(c, k, j + 1) - a)
                total += 0.5 * n.norm()
            out[cells.entity_id(c)] = total

    mesh.topology.faces()                            # the faces kernels walk
    areas = tack.empty((mesh.num_cells,))
    td.for_each(surface_areas, mesh, "cells", areas)

    polyhedra = td.as_polyhedra(mesh)                # every cell a polyhedron
    same = tack.empty((polyhedra.num_cells,))
    td.for_each(surface_areas, polyhedra, "cells", same)

    The complete program compares its shape-based and polyhedral results. The triangle fan is appropriate for the example's planar convex faces; general nonplanar or nonconvex faces require a deliberate geometric interpretation. For supported built-in measures, prefer td.cell_geometry and td.face_geometry.

    Keep parallel ownership explicit¶

    The safe pattern is one writer per cell or face output. A face kernel that adds to both neighbouring cells is a scatter; concurrent faces can target the same cell and require atomics or a separate gather pass. A barrier cannot order all mesh groups. Keep globally dependent stages in separate launches.

    Allocate and derive topology before the repeated calculation. Time first-use group construction and compilation separately from warm calls. Scalar model parameters can change between calls without changing the source, but a new cell shape or space layout can require another specialization.
