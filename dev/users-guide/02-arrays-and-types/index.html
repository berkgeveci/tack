    Arrays and Types¶

    Arrays hold the state that kernels read and write. Copy input values from NumPy, allocate an output, then check the downloaded result. The introductory grid examples use (height, width) and [row, column].

    An array from input to output¶

    Save this complete example in a .py file:

    import numpy as np
import tack

tack.set_default_device("cpu")
host = np.arange(6, dtype=np.float32).reshape(2, 3)
source = tack.array(host)                          # copy input values
out = tack.empty(host.shape)                       # every output will be written

@tack.kernel
def add_one(source, out):
    for row, column in tack.ndindex(source.shape[0], source.shape[1]):
        out[row, column] = source[row, column] + 1.0

add_one(source, out)
np.testing.assert_array_equal(out.numpy(), host + 1.0)
print(out.numpy())                                 # [[1. 2. 3.], [4. 5. 6.]]

    array copies its NumPy input, keeping its dtype (here f32); numpy also returns a copy. Choose tack.zeros when a kernel needs an initial value of zero, and tack.empty when you will write every value before reading it. Both make f32 arrays unless given a dtype. Allocate arrays once and reuse them across timesteps.

    Use tack.f32 for a portable starting point for real-valued data and tack.i32 for ordinary indices. The scalar type table lists the other widths; precision details cover promotion and wrapping when your calculation needs them.

    Arrays¶

    tack.Array is typed storage on a backend. tack.empty allocates it; tack.array copies existing values into it. Both are functions, hence their lowercase names. A dataset tack.dataset.Field is a different object: a space plus its coefficient values on a topology.

    import numpy as np
import tack

tack.set_default_device("cpu")
velocity = tack.empty((4,), tack.vec3(tack.f32))
velocity.fill([1.0, 0.0, 0.0])
assert isinstance(velocity, tack.Array)
assert velocity.shape == (4,) and velocity.dtype is tack.vec3(tack.f32)
np.testing.assert_array_equal(velocity.numpy(), np.tile([1.0, 0.0, 0.0], (4, 1)))

    An array's shape counts elements. Its dtype describes one element: scalar, fixed-size vector or fixed-size matrix. A scalar array of shape (4, 3) and a vector array of shape (4,) with dtype vec3(f32) both contain 12 scalars, but a kernel reads a scalar from the former and a 3-vector from the latter.

    Construction Array shape Element type NumPy download shape
    tack.empty((n,)) (n,) f32 scalar (n,)
    tack.empty((n,), tack.vec3()) (n,) Three f32 components (n, 3)
    tack.empty((n,), tack.mat3()) (n,) 3x3 f32 matrix (n, 3, 3)

    vec2, vec3, vec4, mat2, mat3 and mat4 default to f32 components (the default float type; see below). Use vec(n, dtype) for another width and mat(rows, columns, dtype) for a rectangular matrix (up to 4x4). These functions describe types; they do not allocate arrays.

    The shape comes first and the dtype second, as in NumPy. A dtype is a Tack type or anything NumPy accepts as one (np.int32, "float64"); without one, an allocation is f32 (the default float type). The same allocation functions work for every element type:

    # 1D array
data = tack.empty((1024,))

# 2D array (linearized internally)
grid = tack.empty((100, 100))

# Integer array
indices = tack.empty((256,), tack.i32)
counts = tack.empty((256,), np.int32)      # the same type, named by NumPy

    A new array's contents are unspecified, on every backend, until a kernel, tack.copyto or fill writes them. tack.zeros(shape, dtype) makes an array of zeros (ones and full likewise), filled on the device.

    Copy values or allocate without copying¶

    tack.array(values, dtype=None) always creates independent storage and copies values. With no dtype it infers a scalar type and uses every input dimension as an array dimension. A NumPy array keeps its dtype (a float64 array gives an f64 array); Python floats give f32 and Python ints i32, or i64 if a value needs it. It never guesses vector or matrix elements:

    positions = tack.array(np.zeros((10, 3), np.float32), dtype=tack.vec3())
scalars = tack.array(np.zeros((10, 3), np.float32))
assert positions.shape == (10,)
assert scalars.shape == (10, 3)

    An explicit vector or matrix dtype consumes matching trailing input dimensions. A mismatch raises ValueError. Lists are accepted too. tack.asarray(values, dtype=None) is the same, except that it returns a Tack array of the requested dtype (or any, without one) as it is, without a copy.

    tack.empty_like(prototype) reads only shape and type metadata, allocates independent storage on the prototype's device (or device=), and leaves values uninitialized. It preserves a Tack array's element type. A scalar dtype override changes the component type; an element dtype override selects a new element type:

    scratch = tack.empty_like(positions)                 # ten vec3(f32) elements
integer_positions = tack.empty_like(positions, dtype=tack.i32)  # vec3(i32)

    For scalar values:

    # Create an array from a numpy array (infers shape and dtype)
x = tack.array(np.arange(1024, dtype=np.float32))

# Override dtype
y = tack.array(some_array, dtype=tack.f32)

    Or allocate first, then copy into the existing array:

    data = tack.empty((1024,))
tack.copyto(data, np.arange(1024, dtype=np.float32))
tack.copyto(data, 0.5)                     # a scalar broadcasts

# Copy data back to numpy
result = data.numpy()
same = np.asarray(data)                    # also a copy

    tack.copyto(a, host) is strict, like np.copyto: host must have the shape of a.numpy() or broadcast to it, and its values are converted to a's dtype. Given another Tack array, tack.copyto(dst, src) copies on the device. The destination is always a Tack array: copyto writes into Tack storage, and numpy() reads it back into a new NumPy array. Between two NumPy arrays, use np.copyto. Arrays are not assigned with a[...] = values.

    On Metal (Apple Silicon), arrays use shared memory — copyto/numpy are simple memory copies with no DMA transfers. On CUDA, HIP and Level Zero, these are explicit host-device copies. On every GPU backend they take their place in order with the queued launches: copyto does not overtake a launch that still reads the old values, and numpy waits for the launches before it (see When a call returns).

    Array Access in Kernels¶

    @tack.kernel
def double(data):
    for i in range(data.shape[0]):
        val = data[i]           # 1D access
        data[i] = val * 2.0

@tack.kernel
def clear(grid):
    for idx in range(grid.shape[0] * grid.shape[1]):
        grid[idx] = 0.0         # Flat indexing into 2D array

    A kernel has exactly one parallel loop, so independent loops go in separate kernels.

    Indexing¶

    An array takes one index per dimension, img[i, j], or a single flat, row-major index, img[k]. A kernel given an array whose number of dimensions does not match the number of indices raises TypeError at the call, with the source position: grid[i, j] on a three-dimensional array would otherwise address some other element silently. A vector of integers supplies one index per component, so grid[cell] is grid[cell[0], cell[1]].

    Vector and Matrix Arrays¶

    An array can hold a small vector or matrix in each element:

    pos = tack.empty((n,), tack.vec3(tack.f32))        # a 3-vector per element
vel = tack.empty((height, width), tack.vec2(tack.f32))  # on a 2-D grid
F = tack.empty((n,), tack.mat2(tack.f32))       # a 2x2 matrix per element

    In a kernel pos[i] is the whole vector and F[i] the whole matrix; see Vectors and Matrices for what can be done with them. The storage is one flat array with the components of each element together (a matrix in row-major order).

    On the host, the components are trailing NumPy dimensions:

    tack.copyto(pos, points)                 # points has shape (n, 3)
points = pos.numpy()                     # (n, 3)
flat = pos.numpy().reshape(-1)           # flatten the downloaded copy
tack.copyto(F, gradients)                # gradients has shape (n, 2, 2)
gradients = F.numpy()                    # (n, 2, 2)
pos.fill([0.0, 1.0, 0.0])                # every element to this vector
pos.fill(0.0)                            # every component to this scalar

    A flat (n * 3,) array is not accepted by copyto for a vector array; reshape it to (n, 3) first.

    Structure of Arrays¶

    A vector or matrix array can instead keep each component in an array of its own: the structure-of-arrays layout, as a simulation often hands over its coordinates. tack.soa(x, y, z) makes a vec3 array from three arrays that exist already, without copying, so they can come from another library (tack.from_dlpack, tack.array_from_ptr) on the CPU or a GPU; layout="soa" on a constructor makes new ones:

    import numpy as np

import tack

tack.set_default_device("cpu")


@tack.kernel
def advance(pos, vel, dt):
    for i in range(len(pos)):
        pos[i] += vel[i] * dt


x, y, z = (np.zeros(4, np.float32) for _ in range(3))   # someone else's arrays
pos = tack.soa(tack.from_dlpack(x), tack.from_dlpack(y), tack.from_dlpack(z))
vel = tack.full((4,), [1.0, 2.0, 3.0], tack.vec3(), layout="soa")
advance(pos, vel, 0.5)
assert np.allclose(y, 1.0)                     # written through to their memory
assert pos.layout == "soa" and pos.components[1].size == 4
assert np.allclose(pos.numpy(), [[0.5, 1.0, 1.5]] * 4)

    Kernels index an SOA array exactly as an interleaved one (pos[i], pos[i].y, pos[i] += v, atomics with a vector), and the same kernel takes either layout, compiling one variant for each; only a scalar atomic at a flat component index is interleaved-only. On the host it reads and writes as any vector array (numpy(), copyto, fill, reductions); a.components gives the component arrays back, and tack.array(a, layout="aos") copies it into one interleaved buffer. With no one buffer, it is not exported whole through DLPack or to VTK; its components are.

    Reading One Element from the Host¶

    f[i], f[i, j] and f[()] (for a zero-dimensional array) read one element in host code: a Python number from an array of scalars, a NumPy array from a vector or matrix array. Negative indices count from the end.

    head = queue[()]                   # a counter a kernel maintains
comet = pos[0]                     # a 3-vector, as a NumPy array
if temperature[i, j] > melting:    # a host-side decision on one value
    ...

    This is for inspection and for decisions on single values. On CPU and Metal it reads unified memory directly; on the other backends every read is a transfer of that one element, so many elements are read at once with numpy(). Arrays are not written by element from the host: build the values in a NumPy array and tack.copyto them, fill the array, or write them in a kernel. Iterating an array raises for the same reason.

    A scalar shared between launches¶

    A zero-dimensional array holds one logical element, accessed as f[()], NumPy's spelling, in kernels and on the host (f[None] is refused):

    strength = tack.empty(())
strength.fill(2.0)

@tack.kernel
def add_strength(data, strength):
    for i in range(data.shape[0]):
        data[i] += strength[()]

    Use a scalar argument for a host-supplied value that simply changes per call. A scalar array is useful when kernels also compute or retain that value. A zero-dimensional vector array works similarly: gravity = tack.empty((), tack.vec2()) and gravity.fill([0.0, -9.8]).

    Reductions¶

    data.sum(), data.min(), data.max() and data.mean() reduce every scalar component of an array and return a Python float; statistics such as var, norm and histogram are in tack.algorithms. Vector and matrix components are reduced together, and mean() divides by the scalar component count. See Reductions and Scans for where each runs, its accumulator type and its NaN and empty-array behavior.

    Array Utilities¶

    Allocate matching storage without copying¶

    Use tack.array(host) when you need a copy of existing values. Use tack.empty_like for an output or scratch array that will be written before it is read:

    source = tack.array(np.arange(8, dtype=np.float32))     # copies values
out = tack.empty_like(source)                           # same shape and dtype
integer_out = tack.empty_like(source, dtype=tack.i32)   # override dtype
grid_out = tack.empty_like(np.empty((4, 8), dtype=np.float32))  # no upload

    The prototype may be a NumPy array or Tack array. Storage is independent, writable and allocated on a Tack prototype's device, a NumPy prototype's on the default device. Vector and matrix array prototypes retain their logical shape and component dimensions. A NumPy array produces a scalar array of the same shape, including any trailing dimensions. No values are copied or initialized; write every value before reading it. tack.zeros_like, tack.ones_like and tack.full_like(prototype, value) allocate the same way and fill the new array.

    The kernel helpers local_array_like(array, size) and shared_like(array, size) also copy no values. They inherit the scalar component dtype and use the explicitly supplied scratch size; see Advanced Features.

    Constructors¶

    # Allocate filled arrays
x = tack.zeros((1024,))                         # f32
y = tack.ones((256,), tack.i32)
z = tack.full((100,), 3.14)                     # f32, from the Python float
c = tack.full((100,), 7)                        # i32, from the Python int
idx = tack.arange(64)                           # [0, 1, 2, ..., 63] as i32
idx_f = tack.arange(64, dtype=tack.f32)         # [0.0, 1.0, ..., 63.0]
odd = tack.arange(1, 64, 2)                     # [1, 3, ..., 63]

    Copy, Convert, Reshape¶

    # Copy (new array, separate buffer)
backup = data.copy()

# Convert dtype (returns new array)
data_f64 = data.astype(tack.f64)
indices_u8 = indices.astype(tack.u8)

# Reshape (metadata only, shares buffer — no copy)
flat = grid.reshape(-1)                  # -1 is inferred from the size
grid2d = flat.reshape(height, width)     # or reshape((height, width))

    Concatenate¶

    # Concatenate 1D arrays (same dtype required)
combined = tack.concat([part_a, part_b, part_c])

    Size and Length¶

    f = tack.empty((4, 3))
f.size       # 12 (total elements)
f.ndim       # 2
len(f)       # 4 (first dimension)
f.nbytes     # 48 (bytes of storage)

v = tack.empty((4,), tack.vec3())
v.size, v.ndim, v.nbytes   # 4, 1, 48: elements, not components

    Implicit Arrays¶

    tack.arrays has arrays that compute each value from its index instead of storing it: CountingArray, ConstantArray, CartesianProduct, UniformCoordinates, Permutation, Concatenate, View, Strided, Components, Function, Transform, Cast and random arrays. They compose, and a kernel indexes them as it indexes a stored array, so a kernel written for stored arrays takes them unchanged:

    import numpy as np

import tack
from tack import arrays

tack.set_default_device("cpu")


@tack.kernel
def scaled(a, out, s):
    for i in range(len(a)):
        out[i] = a[i] * s


out = tack.zeros((4,))
scaled(tack.array([1.0, 2.0, 3.0, 4.0]), out, 2)       # a stored array
scaled(arrays.CountingArray(4, 1.0, 1.0), out, 2)       # 1, 2, 3, 4 computed
ids = tack.array([3, 0, 2, 1])
scaled(arrays.Permutation(ids, arrays.CountingArray(4, 0.0, 10.0)), out, 1)
assert np.allclose(out.numpy(), [30, 0, 20, 10])

    Each kind of array compiles its own variant of the kernel, and a composed array inlines to the expression you would write by hand.

    Arrays that wrap stored ones can also be written through: a store into a View, Strided or Permutation (a scatter) lands in the array it wraps, Components(x, y, z) takes a vector and writes each component to its own array (a structure of arrays, which tack.soa also stores; see Structure of Arrays), Concatenate writes into the part that holds the index, and ExtractComponent writes one component. An array is writable exactly when what it writes through is: a store into a CountingArray, a Function, or a Permutation of one, is refused when the kernel compiles, and a read-only stored array stays read-only behind any wrapper. Your own classes join the same way: see Indexable Objects. The dataset reference lists every implicit array with its VTK and Viskores counterparts.

    Scalar Types¶

    Tack provides these scalar types:

    Type Description Numpy equivalent
    tack.i8 8-bit signed int np.int8
    tack.u8 8-bit unsigned int np.uint8
    tack.i16 16-bit signed int np.int16
    tack.u16 16-bit unsigned int np.uint16
    tack.i32 32-bit signed int np.int32
    tack.u32 32-bit unsigned int np.uint32
    tack.i64 64-bit signed int np.int64
    tack.u64 64-bit unsigned int np.uint64
    tack.f32 32-bit float np.float32
    tack.f64 64-bit float np.float64

    GPU backends use f32 by default. Python float scalar arguments are automatically promoted to f64 when any array argument uses f64, preventing silent precision loss. Otherwise, float scalars default to f32.

    The default float type¶

    f32 is the float type arrays get when nothing chooses one. A program that works in double precision throughout can make it f64 once:

    tack.set_default_float(tack.f64)     # tack.get_default_float() reads it

x = tack.zeros((n,))                 # f64
v = tack.empty((n,), tack.vec3())    # three f64 components
y = tack.array([0.1, 0.2])           # f64: Python floats follow it
z = tack.array(host_f32)             # f32: a NumPy array keeps its type

    It covers empty, zeros and ones without a dtype, Python floats in array, full and arange, vec/mat types without a component type, tack.arrays' implicit arrays, and tack.dataset's constructors, sources and readers (uniform_grid, DataSet, vtk_to_dataset, mfem_to_dataset, ...). Kernels don't change: their precision follows the arrays they are given, so a kernel given f64 arrays computes in f64 either way. The setting is process-wide, like the default device, and arrays already made keep their type. Metal has no f64, so with f64 the default there, an array made without a dtype raises TypeError naming the setting.

    Scalar Arguments¶

    Kernels accept Python scalars directly — no need to wrap them in arrays:

    @tack.kernel
def saxpy(x, y, out, alpha, n):
    for i in range(n):
        out[i] = alpha * x[i] + y[i]

saxpy(x, y, out, 2.5, 1024)  # alpha=2.5, n=1024 passed as scalars

    Scalars are automatically packed into constant buffers on GPU backends that have binding limits (like Metal's 31-buffer limit). You can use as many scalar arguments as you need.

    Both Python types and numpy scalar types (np.float32, np.int32) work. Integer arguments use i32 when their value fits, then i64, then u64 for positive values above the signed 64-bit maximum. Values below -2^63 or above 2^64 - 1 are rejected. Integer literals follow the same rule.

    Type Casts¶

    Inside kernels, int() and float() cast to i32 and f32 respectively. For explicit control over the target type, use the Tack type cast functions:

    @tack.kernel
def precise_compute(x, out):
    for i in range(x.shape[0]):
        val = tack.f64(x[i])      # promote to double precision
        out[i] = tack.f32(val)    # back to single

@tack.kernel
def bitwise_ops(data, out):
    for i in range(data.shape[0]):
        bits = tack.u32(data[i])  # unsigned for bitwise ops
        out[i] = tack.i32(bits >> 8)

    Available casts: tack.i8(), tack.u8(), tack.i16(), tack.u16(), tack.i32(), tack.u32(), tack.i64(), tack.u64(), tack.f32(), tack.f64().

    Note: tack.f64() is not supported on Metal (Apple GPUs lack double precision), and an f64 array can't be made there: tack.empty(n, tack.f64) raises TypeError with Metal as the default device.

    Precision and integer arithmetic¶

    Start with explicit input dtypes and cast where the computation needs a different precision. An f64 output alone does not widen integer division: write tack.f64(a) / tack.f64(b) for a double-precision quotient. Integer arithmetic wraps at its inferred width. Expand the details when these rules affect your calculation.

    Literal precision, promotion, wrapping, division and powers

    Float literals in a kernel take the precision of what they meet, the way NumPy treats Python scalars. With an f64 array x, x[i] * 0.1 computes in f64 with the f64 nearest 0.1, and tack.f64(0.1) is that value exactly. A literal on its own or beside only integers is f32. A local assigned once, to literals (a = 0.1), behaves like the literal wherever it is read, so x[i] * a is exact too. A local assigned only literals more than once is f64 in a kernel with an f64 array, as float scalar arguments are. The language contract has the full rule.

    Integer arithmetic (+, -, *, negation, and bitwise operations) wraps at the expression's fixed width. Integer casts and stores keep the low bits at the destination width: tack.u8(-1) is 255, and tack.i8(255) is -1. Widening preserves the source value before wrapping; tack.i64(tack.u8(255)) is 255. Each intermediate operation wraps at its own inferred width.

    Integer promotion preserves both input ranges. For example, i8 + u16 uses i32, and i32 + u32 uses i64. Combining a signed type with u64 requires an explicit cast, including comparisons. To add an unsigned literal, write value + tack.u64(1). Choose a signed cast instead if signed wrapping is intended. Integer min/max use exact values; abs retains the input type, so the signed minimum stays negative under the wrapping rule.

    Integer / produces an f32 quotient: 7 / 2 is 3.5. For f64 precision, explicitly cast the operands, for example tack.f64(a) / tack.f64(b); an f64 output array alone does not change the intermediate precision. An evaluated integer divisor must be nonzero. With a floating operand, division uses the promoted floating precision.

    Integer ** and two-argument pow preserve the base type and compute exact power modulo its width. For an i8 base, 3 ** 5 is -13, regardless of the exponent's integer width. Signed/u64 pairs are accepted for both true division and power because their type rules differ from integer promotion. Integer exponents must be nonnegative; negative literals are rejected. 0 ** 0 is 1. Cast the base to floating point for negative powers or floating results: tack.f32(a) ** e. With a floating operand, both power operands use the promoted floating precision.

    Shifts keep the left operand's type. Counts must be integers from zero up to one less than that type's width. Unsigned right shifts fill with zeros; signed right shifts fill with the sign bit. Float-to-integer conversions truncate toward zero and require finite input with a representable truncated value. See the language contract for division constraints and numerical policies still under development.

    Device Pointer Interop¶

    For interop with external libraries (pycuda, cupy, Catalyst/in-situ), you can wrap an existing device pointer as a Tack array without copying:

    # Wrap a CUDA device pointer (read-only by default)
array = tack.array_from_ptr(cuda_device_ptr, (n,), tack.f32)

# Wrap with write access
array = tack.array_from_ptr(ptr, (n,), tack.f32, writable=True)

    The array does not own the memory — Tack will not free it. On CPU, you can pass a numpy array directly. On Metal, pass an MTLBuffer object. On CUDA/HIP/Level Zero, pass the device address as an integer (a NumPy integer or a CUdeviceptr works too); a host address is rejected with ValueError. A launch that uses a wrapped pointer completes before the call returns, so the memory's owner can read the results at once.

    Read-only arrays raise an error on tack.copyto() and fill(), and a kernel call that passes one where the kernel may store to it raises ValueError before the kernel runs. Kernel reads work normally.

    For layout, views and simultaneous accesses, see Memory and parallel correctness. For DLPack and borrowed allocations, see Sharing arrays with other libraries.
