# AST Transform

The AST transformer (`ast_transform.py`) converts a Python function's AST
into Tack IR. It is the largest single frontend file and the heart of
the frontend.

## Entry Point

```python
# In kernel.py, when get_ir() is called:
from tack.lang.ast_transform import transform_kernel
ir_module = transform_kernel(ast_tree, vector_fields=..., texture_fields=...,
                             python_func=kernel.func, template_funcs=...)
```

`transform_kernel` creates a `KernelTransformer` (an `ast.NodeVisitor`)
and visits the module. The result is an `IRModule` containing one
`IRFunction`.

`call_bindings.py` supplies static device-call resolution from the defining
Python callable and transformation-local template method map. AST-only
callers can supply an explicit `bindings` dictionary. Bare kernel intrinsics
remain available without a Python import; device functions require a bound
`Func` object. No global function-name registry is consulted.

Original kernel source is validated by `source_validation.py` before
transformation. Original `@tack.func` bodies are also validated before
return restructuring or variable renaming, so unreachable unsupported
syntax cannot disappear. Unsupported constructs raise
`UnsupportedSyntaxError`, a `NotImplementedError` subclass, with the function
name, construct, and line/column in captured, dedented source. The
transformer's default visitor also rejects unknown nodes. Docstrings and
`pass` are explicit no-ops; decorators and annotations are host metadata.

## KernelTransformer State

The transformer tracks several pieces of state:

- **`_loop_depth`** — 0 at the top level. The `for i in range(...)` at
  depth 0 becomes `IRParallelFor`; nested loops become `IRSequentialFor`.
- **`_in_parallel_loop`**, **`_parallel_loop_seen`** and **`_kernel_body`**
  — enforce the one-loop rule and the outside-the-loop rule.
  `_visit_parallel_for` accepts one `for` statement directly in the kernel
  body; a second one, or one inside a top-level `if` or `while`, raises
  `UnsupportedSyntaxError`, as does a kernel with none. While
  `_in_parallel_loop` is false, `_visit_body` passes each lowered statement
  to `_check_outside_parallel_loop`, which rejects a field or array store,
  atomic, barrier, block reduction or `print` (`_effect_name`) at the
  statement's source position. It runs on the lowered IR so effects from
  inlined device functions and template methods are seen; nested bodies
  are visited first, so the reported position is the innermost one.
- **`_inline_counter`** — monotonic counter for generating unique variable
  names during `@tack.func` inlining.
- **`_vector_vars`** — tracks which local variables are vectors (name → component count).
- **`_vector_fields`** — tracks which parameters are vector fields (for scalarization).
- **`_texture_fields`** — tracks which parameters are textures (for `tex.sample()`).
- **`_texture_origin`** — maps renamed texture names back to original parameter names
  (needed when textures pass through `@tack.func` inlining).
- **`_shared_vars`** — names of `tack.shared()` and `tack.local_array()` variables
  (affects indexing — these are arrays, not scalars).
- **`_pre_stmts`** — statements generated by expression-level inlining
  that must execute at the expression's original position. Reentrant body
  traversal preserves the surrounding expression's pending statements.

## Expression Evaluation

`_visit_expression` isolates an expression's value and prerequisite
statements. `_visit_ordered` visits operands left to right and materializes
earlier loads before a later operand's inlined effects. Boolean and
conditional expressions put those prerequisite statements inside `IRIf`
guards, rather than moving them before the guard. Inlined `while` conditions
are lowered into an always-entered loop with condition statements and a
guarded `break`, so `continue` reevaluates the condition.

Augmented stores reuse a single evaluated address and retain the old load
before right-hand-side effects. Sequential `range` bounds and steps are
captured before the loop. CPU codegen also short-circuits pure `IRBoolOp`
and `IRIfExp` expressions with branches and phi joins. Comparisons and
logical expressions yield normalized i32 values `0`/`1`.

See the [kernel language contract](../reference/language-contract.md) for
the supported subset and numerical decisions still open.

## Loop Handling

### Parallel For

At loop depth 0, `for i in range(n)` becomes:

```
IRParallelFor(var="i", start=IRConstant(0), end=IRName("n"), body=[...])
```

With `range(start, end, step)`, Tack transforms the step into a
contiguous-index parallel loop with a decomposition assignment:

```python
# for i in range(0, 100, 3) becomes:
# for __step_idx__ in range(0, ceil(100/3)):
#     i = 0 + __step_idx__ * 3
```

### Sequential For

At loop depth > 0, `for` loops become `IRSequentialFor`. The `step`
attribute is preserved (used by codegens for the C for-loop increment).
Bounds and steps are captured once before entry. Loops inside `while` are
also sequential. Literal zero and negative steps are rejected; dynamic
steps must be positive. A `break` from the outer parallel loop is rejected,
while nested sequential `break` and both forms of `continue` are supported.

### ndrange

`for i, j in tack.ndrange(w, h)` is decomposed into a 1D parallel loop
with index arithmetic:

```
i = __idx__ % w
j = __idx__ // w
```

## Function Call Dispatch

`visit_Call` is the most complex method. It handles:

1. **Math builtins** (`sqrt`, `sin`, etc.) → `IRCall`
2. **`tack.atomic_add/min/max`** → `IRAtomicOp`
3. **`tack.shared(dtype, size)`** → `IRSharedAlloc`
4. **`tack.local_array(dtype, size)`** → `IRLocalAlloc`
5. **`tack.barrier()`** → `IRBarrier`
6. **`tack.thread_id()`** → `IRThreadId`
7. **`print(...)`** → `IRPrint`
8. **`int()`, `float()`** → `IRCast`
9. **`tex.sample(u, v, w)`** → `IRTextureSample`
10. **Vector methods** (`.normalized()`, `.dot()`, `.cross()`) → scalarized ops
11. **`@tack.func` calls** → inlined via `_inline_func_call`

## Assignment Handling

`visit_Assign` checks for several special forms before falling through to
a plain `IRAssign`:

1. **Shared/local allocation**: `smem = tack.shared(...)`, `arr = tack.local_array(...)`
2. **Vector construction**: `v = tack.Vector([a, b, c])`
3. **Multi-dimensional field store**: `field[i, j] = val` → linearized index
4. **Tuple unpacking**: `a, b = func()` → multiple `IRAssign` nodes

## Vector Scalarization

Vector operations are expanded at the AST level. A vector variable `v` with
3 components becomes 3 scalar variables `v__0`, `v__1`, `v__2`. Binary ops
on vectors produce component-wise IR nodes:

```python
# v = a + b  (where a, b are 3-vectors) becomes:
v__0 = a__0 + b__0
v__1 = a__1 + b__1
v__2 = a__2 + b__2
```

Field loads/stores are similarly scalarized: `v = field[i]` loads
`field[i*3]`, `field[i*3+1]`, `field[i*3+2]`.
